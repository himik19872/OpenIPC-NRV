# Мобильное приложение (Android)

Приложение для сервера видеонаблюдения: выбор сервера, онлайн-просмотр
камер и архив записей.

## Возможности

| Экран | Что делает |
|---|---|
| **Серверы** | Список сохранённых серверов, добавление по IP-адресу, порту или DNS-имени, проверка связи |
| **Вход** | Вход по логину и паролю, токен сохраняется для каждого сервера отдельно |
| **Камеры** | Плитки с превью-кадрами, статус онлайн/офлайн, обновление кадров раз в 10 секунд |
| **Просмотр** | Онлайн-видео по HLS, переключение основного и дополнительного потока, пауза |
| **Архив** | Список записей с фильтром по камере, встроенный плеер, подгрузка при прокрутке |

## Подключение к серверу

На экране «Серверы» нажмите **Добавить сервер** и укажите адрес в любом виде:

| Ввод | Что получится |
|---|---|
| `192.168.1.10` | `http://192.168.1.10:8080` |
| `192.168.1.10:9000` | `http://192.168.1.10:9000` |
| `nvr.local` | `http://nvr.local:8080` |
| `https://cam.example.com` | `https://cam.example.com` (порт 443) |

Правила разбора:

- схема не указана → подставляется `http`
- порт не указан → подставляется `8080` (порт сервера NVR)
- переключатель **HTTPS** добавляет схему, если её не написали вручную
- явно указанная схема в поле ввода всегда важнее переключателя

Кнопка **Проверить связь** обращается к публичному `/health` сервера — это
можно сделать до сохранения, чтобы поймать ошибку в адресе или порту сразу.

> **Порт 8080** — это API сервера. Порты HLS (8888), WebRTC (8889) и внешнего
> RTSP (9784) приложению не нужны: видео идёт через API.

## Как воспроизводится видео

**Онлайн.** Приложение открывает HLS-плейлист через API сервера:
`/api/v1/cameras/{id}/hls/index.m3u8?token=<jwt>`. Токен идёт в query-параметре,
потому что плеер не умеет отправлять заголовок `Authorization`.

По умолчанию включается **дополнительный поток** (обычно 704×576): он заметно
экономичнее по трафику и заряду батареи. Кнопкой можно переключиться на
основной (1920×1080).

**Архив.** Записи хранятся готовыми файлами MP4, плеер играет их с
поддержкой перемотки: сервер отдаёт файл через
`/api/v1/recordings/file?path=...`.

> **HEVC (H.265).** Если камера пишет в H.265, часть телефонов такие записи не
> воспроизводит. Приложение сообщает об этом понятным текстом. Решение —
> переключить камеру на H.264 в её настройках.

## Что приложение НЕ использует

Сервер отдаёт в ответе `/cameras/{id}/stream` поля, которые с телефона
не работают, и приложение их игнорирует:

| Поле | Почему не используется |
|---|---|
| `webrtc_url` | Содержит внутренний адрес вида `localhost:8889` |
| `rtsp_url` | Содержит `localhost:8554`, плюс RTSP требует отдельного плеера |
| `snapshot_url` | Адрес камеры в её локальной сети, недоступен с телефона |

Ссылки `hls_url`, `main_hls_url`, `sub_hls_url` и `url` записей сервер отдаёт
**относительными** — приложение приклеивает к ним адрес выбранного сервера.

## Сборка

### Что нужно

| Компонент | Версия | Проверка |
|---|---|---|
| Node.js | 18 или новее | `node -v` |
| JDK | **17** (не 21!) | `java -version` |
| Android SDK | платформа 34, build-tools 34 | `sdkmanager --list_installed` |

> **JDK 17 обязателен.** На JDK 21 сборка падает с ошибкой
> `jlink executable ... does not exist`: Android Gradle Plugin вызывает
> `jlink` из JDK 21, а тот несовместим с `core-for-system-modules.jar`
> платформы 34.

### Установка Android SDK

```bash
mkdir -p ~/Android/Sdk/cmdline-tools && cd ~/Android/Sdk/cmdline-tools
curl -sSL -o tools.zip \
  "https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip"
unzip -q tools.zip && mv cmdline-tools latest && rm tools.zip

export ANDROID_HOME=$HOME/Android/Sdk
export PATH=$PATH:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools

yes | sdkmanager --licenses
sdkmanager "platform-tools" "platforms;android-34" "build-tools;34.0.0"
```

Добавьте в `~/.bashrc`:

```bash
export ANDROID_HOME=$HOME/Android/Sdk
export PATH=$PATH:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools
```

### Сборка APK

```bash
cd mobile
npm install

# Путь к SDK — один раз на проект.
echo "sdk.dir=$HOME/Android/Sdk" > android/local.properties

cd android
JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ./gradlew assembleDebug
```

Готовый файл: `mobile/android/app/build/outputs/apk/debug/app-debug.apk`.

Debug-сборка получается большой (~155 МБ), потому что содержит библиотеки
для всех архитектур процессора. Для установки на конкретный телефон
соберите только нужную архитектуру:

```bash
./gradlew assembleDebug -PreactNativeArchitectures=arm64-v8a
```

Такой APK будет примерно в четыре раза меньше.

### Установка на телефон

1. Включите на телефоне **Параметры → О телефоне → 7 раз нажать на «Номер
   сборки»** — появятся параметры разработчика.
2. В параметрах разработчика включите **Отладка по USB**.
3. Подключите телефон кабелем и проверьте, что он виден:

```bash
adb devices
```

4. Установите приложение:

```bash
adb install mobile/android/app/build/outputs/apk/debug/app-debug.apk
```

Либо просто перенесите APK на телефон и откройте его файловым менеджером —
потребуется разрешить установку из неизвестных источников.

### Запуск с live-reload

Для разработки удобнее Metro, а не сборка APK на каждое изменение:

```bash
cd mobile
npm start                          # в одном терминале

# во втором — при подключённом телефоне
cd android
JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ./gradlew installDebug
adb reverse tcp:8081 tcp:8081      # Metro доступен телефону
```

## Решения, о которых стоит знать

**Адрес сервера нормализуется.** Пользователь вводит адрес как удобно,
приложение приводит его к виду `http://хост:порт`. Так в базе не появляется
одновременно `192.168.1.10` и `http://192.168.1.10:8080`.

**Токен хранится отдельно для каждого сервера.** Переключение между серверами
не требует повторного входа, а выход с одного не затрагивает другие.

**Токены лежат в AsyncStorage.** Это осознанный выбор ради отсутствия лишних
зависимостей: без root файлы приложения недоступны другим программам. При
работе через публичные сети стоит заменить хранилище на
`react-native-keychain`.

**Превью кадров идут через очередь.** Одновременно запрашивается не больше
трёх кадров: камеры OpenIPC отказывают при большом числе параллельных
запросов, и в списке появлялись бы пустые плитки. Место освобождается только
после получения картинки или ошибки — иначе очередь не ограничивает нагрузку.

**Навигация собрана вручную.** Экранов пять, переходы линейные, поэтому
библиотека навигации не нужна: меньше зависимостей и предсказуемое поведение
кнопки «назад».

**Разрешён незашифрованный трафик** (`usesCleartextTraffic`). Серверы
видеонаблюдения обычно работают по HTTP без сертификата, и без этого
разрешения Android блокирует запросы к ним.

## Известные ограничения

- Проверено на эмуляторе и при сборке; на реальном телефоне с реальными
  камерами не запускалось
- iOS не собирался: проект React Native общий, но сборка под iOS не
  настраивалась
- Просмотр записей в HEVC может не работать на части телефонов
- Push-уведомления о событиях не реализованы
